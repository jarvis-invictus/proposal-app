## Real issues found this session, not previously known
1. **Editor regression**: theme color picker and PDF export button existed in the
   pre-correction editor, dropped when the Editor was rebuilt (Correction 6.4) and never
   rewired. The components (`ThemeColorPicker.tsx`, `PdfExportModal.tsx`, also `AIDock.tsx`,
   `SectionRail.tsx`) still exist fully built with zero usage in `app/` — cheap to fix.
2. **Currency/generation semantic gap**: `ProposalSchemaV1` has no currency field, generation
   prompt never mentions currency. Display formatting (this session's currency work) is correct
   but sits on top of a generation layer with no currency awareness at all — a real correctness
   bug, not yet fixed.
3. **E-signature doesn't meet the real ESIGN Act minimum bar**: accept route captures only name
   + timestamp. No IP/user-agent, no content snapshot at signing time, no explicit consent
   line, no reviewable copy for the signer afterward. Checked directly against the actual code.
4. **Production deployment status is unknown, not just undocumented.** `.env.local` (what this
   whole session ran against) points to local Docker Supabase. `supabase/.temp/project-ref`
   shows a real linked *hosted* Supabase project. `.env.local` has a commented-out
   `OLD_NEXT_PUBLIC_SUPABASE_URL`, implying a prior switch. No `vercel.json`, no other evidence
   of an active deployment found in-repo. **This needs a direct human answer before the launch
   plan's sequencing can be trusted** — see docs/MVP_LAUNCH_PLAN.md §0.
5. **Two lingering console warnings fixed this session** (PR #25, unmerged): the Next.js
   middleware→proxy convention migration (present every build this whole session, nobody had
   acted on it), and a real visual bug — `logo.png` is 542×462, not square, and was being forced
   into a square by the Logo component, meaning the Marg mark rendered slightly distorted on
   every page. Neither was previously flagged anywhere.
6. **`credit_transactions` table**: real migration, real RLS policy, zero rows, zero code
   references anywhere. Scaffolding for `pay_per_proposal` that nothing uses yet.
7. **No conflict resolution on the Editor's autosave** — last-write-wins, no locking, no
   presence indication. Untested (needs two simultaneous sessions to observe). Low risk at
   current scale, real risk once Team is used by more than one person concurrently.

## Standing gotchas worth remembering across sessions (candidates for MEMORY.md)
- Browser automation tool (`mcp__Claude_Browser__computer` clicks) intermittently fails with
  "No node found at given location" — workaround is `javascript_tool` executing
  `element.click()` directly, or a fresh tab/`preview_start`.
- `read_console_messages` retains history across navigations in the same tab — a stale warning
  from three page loads ago will still show. Always verify with a *fresh tab*
  (`tabs_create` + `navigate`) before concluding a warning is still live.
- Docker local Supabase: `docker exec supabase_db_proposal-app psql -U postgres -d postgres -c
  "..."` is the direct-verification pattern used throughout this session — faster and more
  trustworthy than inferring DB state from UI behavior alone.
